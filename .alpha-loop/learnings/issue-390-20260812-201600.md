# Issue #390: session setup failures belong to the structured CLI lifecycle

## What happened

Git rejected a dedicated session worktree because the deterministic session
branch was still checked out in the coordinator repository root. The conflict
correctly prevented child work, but escaped as an uncaught stack trace after the
session manifest had already been created.

## Root cause

`runIssueSession` protected `createSession` and released the session lock in a
`finally` block, but did not translate `ensureSessionWorktree` failures into a
structured command exit or record them in the durable manifest.

## Prevention

- Record session-worktree setup failures at the `worktree` stage.
- Convert them to the CLI's structured exit type with exit code 1.
- Retain the existing cleanup and lock-release `finally` path.
- Assert that no issue or batch pipeline begins after the conflict.
- Before an epic resume, ensure the coordinator checkout is on its configured
  base branch rather than the deterministic session branch.
