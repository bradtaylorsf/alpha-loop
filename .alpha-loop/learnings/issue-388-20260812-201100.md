# Issue #388: setup gates must fail closed across every run mode

## What happened

An epic run used `--batch --batch-size 1`. Its configured worktree setup
command exited nonzero, but `setupWorktree` only warned and returned success.
The first issue therefore entered planning with an invalid environment and the
batch queue was still eligible to start the next issue.

## Root cause

Worktree creation treated dependency and custom setup commands as best-effort.
The sequential pipeline already re-queued worktree failures, but did not mark
them transient; the batch pipeline explicitly marked the same failure
permanent. Both run loops stop only on transient pipeline results.

## Prevention

- Throw when both dependency-install attempts fail.
- Throw when a configured setup command fails.
- Re-queue setup failures as transient in both sequential and batch pipelines.
- Assert that no agent stage runs after setup failure.
- Assert that `--epic --batch --batch-size 1` does not start the next child.
- Preserve the created worktree so a repaired environment can resume it.
